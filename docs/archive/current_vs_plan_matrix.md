# Current vs Plan Matrix

This document compares the refactored 4-phase plan against the current implementation reality in the repository. Its purpose is not to judge whether the plan is good or bad. Its purpose is to prevent a new GPT from assuming that every phase document is already the routine operational baseline.

## How To Read This Matrix

- "Planned behavior" is taken from the refactored brief and Phase 1-4 PRD/task files.
- "Current implementation" is taken from `docs/current_pipeline_status.md`, `README.md`, `main.py`, `run_production.py`, the active phase modules under `egfr_pipeline/`, and currently observed output trees.
- A low-gap row is still useful if that topic is historically easy to misread, especially AFM and LightDock.

## Snapshot

- Biggest divergence: the scientific plan is PPI-first 4-phase, but the routine operational baseline is still Vina-centered.
- Best alignment: fixed 3-state receptor ensemble, PyRosetta as primary Phase 1 evidence, LightDock as active secondary validation, AFM as legacy optional only.
- Main onboarding risk: `run_production.py` phase numbers are operational stages, not the same as the scientific Phase 1-4 plan.

## Practical Conclusion

The repository is not "plan only", and it is not "fully converged to the plan" either. The best current reading is:

1. The scientific target architecture is the refactored 4-phase PPI-first workflow.
2. The routine operational baseline is still Vina-centered with Phase 1 PPI and LightDock as an important parallel evidence branch.
3. Phase 2-4 code and outputs exist and are meaningful, but they should be described as standalone or advanced workflows unless the user explicitly asks to operate on those paths.
